# 技能设计与维护

每个技能应在一个明确问题上改善模型的选择、解释或行动。名称、触发说明、正文与参考资料都服务于这个职责。

## 保持职责明确

AEP 负责解释质量与知识理解。Silly 负责决策依据、处境、资源配置与竞争合作，并自动读取 AEP。两者合成一份回答，Silly 的语气不会成为 AEP 在独立任务中的通用人格。

新增技能之前，先用真实问题判断现有技能是否足够。只有存在稳定、独立的用途时再增加入口。一次失败通常应先修正对应规则，不立即扩成新技能。

## 一份内容，一个归属

`skills/<name>/SKILL.md` 放职责、关键原则、必要约束和按需参考入口。`references/` 保留执行需要的细节。`docs/` 讨论项目理念、研究和维护方法；`examples/` 帮助人理解用法。

技能指令不默认加载项目全部文档，正文也不复制完整参考。更新要沿实际引用检查影响范围，保留每份内容的可维护性。

## 平台适配与依赖

`skills/manifest.json` 是安装器使用的元数据，不是宿主通用规范。它声明依赖与独立调用策略。

AEP 的跨平台源文件只使用通用 frontmatter；Codex 的显式调用策略在 `agents/openai.yaml`，Claude 安装时添加 `disable-model-invocation: true`。Silly 的组合使用由指令中的相对引用实现，安装时必须保留相邻的 AEP 目录。

引用宿主特有功能时说明其实际范围。不要把某个平台的调用格式写成所有客户端都执行的通用协议。

## 验证真实边界

结构检查能够发现坏引用、缺依赖和元数据问题。安装测试需要覆盖首次安装、已有改动、备份、组合依赖和中途失败回退。

行为质量需要独立证据。比较回复时关注事实与关系是否准确、是否回应关键问题、建议能否改变局面，以及是否错误扩大人格判断或价值取舍。风格样稿说明想达到的效果，不证明模型已经稳定做到。

## 小范围迭代

记录具体触发、实际回复、希望改善的判断与反例。每次优先改一个决定性因素，再检查它是否影响其他情境。

维护检查：

```sh
python -m pip install -r requirements-dev.txt
python scripts/check.py
python -m unittest discover -s tests -v
```
