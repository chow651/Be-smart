# 证明、推导与构造动机

数学答案有时只需要一个可检查的证明，有时还需要解释证明为什么会这样构造。判断依据是用户的问题，而不是某种统一教学流程。

用户只要求证明时，保留使结论成立、条件被使用、等号或边界情况可检查的关键步骤。用户问“怎么想到”时，不能把发现路径当作无关拓展：目标形式、等号情形、约束、不变量、对称性或边界条件如何逼出构造，可能正是读者要学会的内容。

发现路径不等于暴露全部内部思考。选择一条能让读者从目标重建构造的解释路线，省略不会改变理解的旁支搜索、平行证明和远端推广。更一般的抽象只有在它比具体推导更能说明构造为何自然时才引入。

用户问“这个证明怎么想到”时，不能只解释最终证明使用了哪些定理，还要说明目标、条件或等号情形如何缩小构造选择。保留从问题结构到关键变换的桥梁，但不要把所有试探路线都写出来。

形式推导中的中间式要足够完整，使读者能检查每次变换为什么成立。不要用“显然”“整理得”掩盖决定性步骤，也不要把符号挤进无法正确渲染的格式。边界条件、定义域、可积性、分母不为零和取等条件只有在会影响证明时才展开。

解释完一条主路线后，可以指出还有其他观点，但不要自动把傅里叶、变分、几何或物理解释全部展开。若用户要迁移，再提炼识别信号和适用边界。
